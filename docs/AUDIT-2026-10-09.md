# ArknightsUID 复查与修复（2026-10-09）

针对当前工作区及本机 GsCore 0.10.5 检查。原有未提交改动继续保留；本轮生产改动集中在刷图规划、掉率处理、抽卡分页和肉鸽难度下载四处，没有新增运行时依赖或通用防御框架。

插件的嵌套包、`__nest__.py`、内层 `Plugins`、业务 `SV`、配置、资源路径、ORM 与定时任务沿用核心接口。与本机 GsCore 的插件骨架一致；真实核心的普通导入、嵌套加载、前缀和唯一任务 ID 回归通过。这是当前安装核心的兼容性结论；插件有自己的 Ruff 配置（88 列、忽略 E402），不能等同于逐项采用父仓库全部格式规则。

## 已复现并修复的问题

| 问题 | 实际影响 | 修复及回归 |
| --- | --- | --- |
| 按掉率截取前 8 关后才选最低理智成本 | 低掉率但低消耗的关卡被排除，刷图及合成对比不一定最优 | 规划使用全部统计结果，展示仍默认前 8 项；用 8 个高成本关加 1 个低成本关经真实 `craft_vs_farm` 入口复现 |
| 掉率统计未检查活动开放时间 | 已结束或未开始的活动关进入刷图规划 | 复用原有 `_is_open`，过滤未开放关；结束时刻本身视为已关闭，永久关不受活动窗口影响 |
| 抽卡分页游标缺失时返回空警告 | 已拉记录保留，但用户不知道旧历史尚未完整拉取 | 保留已拉记录并提示全量重试；同游标重复及 `hasMore=true` 空页同样告知缺口，不再请求到 50 页上限才停止；终页不依赖下一页游标 |
| 肉鸽难度仅用 CDN | 本次 CDN 对傀影表返回 404/超时，整期难度缺失 | 增加同仓库 main 分支源站回退；上游浅克隆确认文件存在，修复后空缓存实网成功取得六期 |
| HTTP 200 的错误 JSON 对象可覆盖难度缓存 | 新响应不能作为难度列表消费，旧有效表也被损坏 | 成功解析成非空列表后才写缓存，否则继续回退或保留旧表；回归覆盖错误对象及 HTML |
| 图片解码失败测试实际没走到解码 | 模拟下载漏返回 200，宽泛异常断言接受了提前触发的 `FileNotFoundError` | 模拟返回 200，精确断言 `UnidentifiedImageError` 并确认缓存残档已删除 |

上述业务回归在修复前已观察到失败，修复后通过。公招检查器自身也新增漏成员、重复成员、错星级、缺标签及尚有分页的失败用例。
