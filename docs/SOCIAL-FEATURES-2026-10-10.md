# 好友查询与公开头像功能实现（2026-10-10）

新增 `arknightsuid_social` 业务模块，已接入核心嵌套加载、强制前缀、账号解析、图片缓存及帮助入口。没有新增运行时依赖、数据库表、全局重试机制或修改个人资料的请求。

## 可用命令

| 命令 | 行为 |
| --- | --- |
| `ark好友 [序号或UID] [页N] [搜索:关键词]` | 默认使用 `ark切换` 的账号；按名称、好友 UID、森空岛昵称筛选，每页 10 人 |
| `ark好友列表` / `ark游戏好友` | 好友查询别名，同样接受参数 |
| `ark头像分类` | 列出公开分类，无需绑定账号 |
| `ark头像列表 [页码] [分类:N]` / `ark头像目录` | 默认明日方舟分类 2，每页 16 张缩略图及稳定的头像 ID |
| `ark头像 <ID> [分类:N]` | 按目录 ID 发送头像图片 |

例如：`ark好友 2 页2`、`ark好友 页1 搜索:博士`、`ark头像列表 2`、`ark头像列表 页2 分类:3`、`ark头像 200232`。搜索字段放在参数末尾；搜索中的数字不会变成账号选择参数。翻页是对已拉取数据的本地分页，不能把它等同于服务端历史分页。

好友头像使用接口的 `avatar.url`；最近在线按官方 UI 已确认的秒时间戳转北京时间，包含年份，0 显示“未提供”；空森空岛昵称与官方一致显示“未授权”。账号 UID 使用现有个人隐藏偏好，好友 UID 使用全局 `HideUid`；渲染上下文不包含原始好友 UID、森空岛用户内部 ID 或凭据，筛选条件只传是否启用的布尔值。

卡片复用 `ark_head.html` 与 `ark_base.css`。图片下载失败时保留目录项目；卡片渲染失败沿用 `send_card_or_text` 发送完整文本回退。长命令注册在短命令前，避免“头像列表/头像分类”被“头像”抢占。

## 接口与缓存

- 好友 GET：`/api/v1/game/friend/list?uid=<已绑定角色UID>`。复用现有 `_signed_request` 的刷新、签名和禁止重定向行为；该请求使用独立的 App 2.2.0 / versionCode 200200057 头，不修改已有接口的 UA/vName。离线协议测试从 HTTP 请求独立重算 HMAC/MD5，并验证失效 token 的刷新重试。
- 好友响应边界接受 `data` 列表或明确的 `data.list`；其它形状报解析失败，不当成空好友。条目使用已恢复的官方 `GameUserInfo` 字段。不猜测未知游标参数。
- `hasMore=true` 时明确提示“尚不完整”，保留已返回好友，且不写完整目录缓存；空的部分结果不会被说成“暂无好友”。
- 完整好友列表按角色 UID 缓存 60 秒，使用现有 `disk_cache` 和 `player_store.assert_uid_segment`。只保存解析后的字段，不保存请求凭据或未知响应字段。接口失败不写缓存。
- 公开头像使用已实网确认的 `/web/v1/user/avatar/category/list` 与 `/web/v1/user/avatars?categoryId=N`，复用现有公共 token/签名；目录缓存 1 小时，图片复用现有头像图片缓存。分类、目录形状和必需字段在外部数据边界校验；不完整目录不缓存为全量。
