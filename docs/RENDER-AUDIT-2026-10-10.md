# 图片渲染与比例实测（2026-10-10）

本轮针对“图片是否渲染准确、比例是否正确”实际生成卡片，并检查解码尺寸、浏览器 DOM、横竖素材和代表性截图。沿用现有模板、预览数据、图片缓存与渲染入口，没有新增渲染器或重做模板。

## 结论与当前配置

只读核对当前保存配置：`RenderEngine=takumi`、`RenderScale=2`、`RemoteRenderEnable=false`。实测环境为 pytakumi 0.1.4、Playwright 1.58.0 / Chromium 151.0.7922.34。

代表卡片与几何样本未发现非等比拉伸，状态卡按原设计宽高比输出；地图保持自然比例，好友头像的 cover 裁切与头像目录的 contain 留白符合模板设置。长卡随内容增加高度，不能要求所有卡片采用同一宽高比。

**Takumi 与 Chromium 的视觉结果不完全一致。** 字体、部分伪元素装饰、分隔线、技能块行高与留白有差异。比例正确及成功出图不代表像素级还原浏览器设计稿。

| 状态卡倍率 | Takumi 输出 | Chromium 输出 |
| --- | --- | --- |
| 1× | 560×358 | 560×359 |
| 2×（当前配置） | 1120×717 | 1120×718 |
| 3× | 1680×1075 | 1680×1077 |

状态卡设计稿为 1000×640，经 `scale(.56)` 进入 560×358.4 CSS px 容器。表中微小高度差来自像素取整和截图边界，没有观察到横纵不同倍率的拉伸。修复后的同引擎倍率切换也已实际验证。

## 本轮修复

1. **Playwright 修改倍率后仍复用旧 DPR。** 页面池原先保留首次创建 context 的像素倍率，运行中从 1× 改为 2×/3×仍可能输出 560px 宽。现在根据倍率切换现有 context/页面代次，清理空闲旧页面；在途页面继续完成，释放后回收。真实回归覆盖 1→2→3→1、在途页面和右下角内容未被裁掉。
2. **图片 cover 裁切可能产生 1px 透明边。** 7×11 的不透明图裁为 61×10 时，浮点计算经 `int` 得到 60px 宽，后续 crop 超出图像范围，产生透明列。现在缩放后的宽高至少覆盖目标范围；修复前 alpha 范围为 `(0,255)`，修复后全图为 `(255,255)`。仍复用原有 PIL 缩放、裁切和缓存流程；已有烘焙缓存未主动清理，旧图需正常缓存清理或原图更新后重烘。
3. **全模板测试未明确选中声称的引擎。** 原“Playwright 全量回归”实际上跟随默认 Takumi，且主要断言文件超过 10KB。现在两个引擎分别覆盖全部 44 张主模板：Playwright 核对真实 DPR、DOM 边界及解码尺寸；Takumi 核对真实调用、完整解码、宽度和非纯色输出，并禁止静默回退冒充成功。
4. **预览工具离线时仍可能下载缺失素材。** `asset_b64` 现在在离线模式只读已有缓存，缺失时返回空，不发起下载。

本轮未发现确凿模板 CSS 比例缺陷，因此没有修改模板或为了两个引擎同高而强行拉伸输出。保留状态卡长昵称的既有省略号行为；好友长昵称和多行说明样本可读。
