# 抽卡、公招与养成规则审查（2026-10-04）

本轮进一步检查计算是否符合游戏规则，而不只看是否成功返回结果。确实发现了原有测试与实现一起写错规则的情况，已修改实现并补充独立验证。

## 确认的问题与修复

| 功能 | 修复前 | 修复后 |
| --- | --- | --- |
| 六星递增概率 | 50 抽未出后每抽增加 2.5 个百分点，第 51 抽为 4.5% | 每抽增加 2 个百分点，第 51 抽 4%、第 52 抽 6%、第 99 抽 100%；垫刀展示参考上限从 80 改为 99 |
| 概率表计算范围 | 把任意计算范围的最后一项置为 100%，且短范围会截断已有垫刀 | 计算 10 抽不代表十抽必得；已有垫刀不受计算范围截断；只对指定单个 UP 的限定模型在 300 抽及以后计入兑换保底，多目标只计实际抽取概率 |
| 默认规划模型 | 默认采用 70% UP 占比，容易被理解为常见限定池中指定一位干员的概率 | 默认双 UP 池中指定一位的 35% 模型；手动单 UP 70% 模型保留。明确说明自动卡池仅提供名称/截止时间，并未自动识别池型 |
| 自动垫刀与卡池选择 | 使用最近一个记录类别的垫刀，可能跨限定池继承；关键词命中多个池时直接选第一个 | 只使用与目标池完整名称相同的本地记录；未知目标池按 0；模糊关键词存在歧义则列出候选 |
| 规划参数与文案 | `目标:0` 变成 300；未知池型静默当单 UP；自定义抽数也被称作井线 | 保留零目标且显示已完成；未知类型返回参数错误；非 300 的资源目标使用“目标”文案，不宣称对应兑换保底 |
| 寻访模拟 | 声称每次十连保底四星；保底重抽可能改变六星比例；缺少某星级池时能把三星干员标成六星 | 明确每次模拟新池首轮，首十抽至少五星；只提升不足五星的结果，不额外重抽六星；降级选取时同步实际星级 |
| 公招推荐 | 不结合招募时长，1/2 星混入九小时组合，压低推荐评级 | 推荐明确附带时长：一般 9:00、支援机械 3:50、新手 7:30，按对应范围筛选；普通标签仍提示可能被划掉 |
| 同选资深/高级资深 | 将两个标签作互斥交集，错误返回空池 | 直接查询按最高稀有度优先；推荐不保留高资+资深的重复浪费标签方案 |
| 多干员养成重复计算 | 按输入文本去重，`史尔特尔 42` 被算作两人 | 按解析后的 `char_id` 去重，材料与请求均只计算一次 |
| 模组进度扣减 | 按列表位置对齐模组，基础证章或 X/Y 顺序差异导致扣错材料 | 用 GameData 模组 ID/类型对应玩家模组等级；忽略基础证章。类型元数据缺失时明确提示未扣除进度，不猜测位置 |
| 多干员库存请求 | 每个干员重新拉库存，合并时可能使用不同快照 | 一次养成计划共用一份库存响应。真实计算链的测试确认两名干员从两次请求降为一次 |

同时移除了模拟中不再使用的保底重新抽样函数；抽卡记录日期沿用前轮统一的北京时间处理。

## 依据与交叉验证

- [PRTS 寻访规则](https://prts.wiki/w/寻访规则)：本轮通过公开 API 读取，规则为连续 50 次未得六星后，下次从 2% 升至 4%，再每次提高 2 个百分点；新池前十抽内至少一名五星或以上，每池一次；不同限定池不继承累计次数。
- [PRTS 公开招募](https://prts.wiki/w/公开招募)：1 小时起为 1–4 星，4 小时起为 2–5 星，7:40 起为 3–5 星；稀有标签另加五星/六星，资深与高资同时选择时优先最高稀有度。
- 本机公开 GameData 模组表：银灰/史尔特尔的 `uniequip_001_*` 为 `ORIGINAL` 基础证章，`typeName2` 为空；升级模组具有独立 X/Y 类型。成本计算不能把基础证章的等级扣到 X 模组上。
- 概率测试不再用第三方黑盒表的宽容差验证 50 抽后的曲线。新增独立“首次六星等待时间 + 更新过程”模型逐点对照 1–299 抽，精度要求为 10 位小数。旧参考表仅用于前 50 抽恒定区的参考比较。

## 范围与限制

- 寻访模拟仍是全干员范围的娱乐模拟，不代表真实卡池干员名单，也不保存跨命令的抽卡进度；界面明确说明每次十连模拟新池首轮。
- 攒抽概率是所选限定模型的估计，不是对标准、中坚、联动、选调和特殊兑换规则的自动识别。自动选择的卡池日期信息不证明对应池型已匹配。
- 养成模组类型来自公开 GameData；本轮没有使用真实账号联调森空岛成本接口，也未声称验证了每种私有响应变体。
- 本轮读查了缓存清理与皮肤目录路径，未确认需要新增修复的问题；这不等同于已经穷尽这些模块的所有场景。
- 修改保存在插件工作区，没有提交、推送或重启机器人。
