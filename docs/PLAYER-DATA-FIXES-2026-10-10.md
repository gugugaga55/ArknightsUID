## 剿灭记录列表被丢弃

第一方 H5 将 `campaign.records[]` 按 `campaignId` 建索引，并使用 `maxKills` 与 `campaignInfoMap[campaignId].name` 展示。依据及原始 JavaScript 摘录见 [2026-10-06 接口调查](ACTIVITY-PROGRESS-API-RESEARCH-2026-10-06.md)。原解析器仅接受字典，列表响应被替换成空字典；现有测试也只构造字典，因此未发现问题。

修复后列表按 ID 归一化，保留旧字典格式。真实 0 击杀保留，缺少 `maxKills` 的记录不生成伪造的 0。剿灭卡和纯文本回退共用 `PlayerData.campaign_name`，从响应元数据取名称；名称缺失时显示 ID。内部仍按 ID 存储，不因关卡同名混合记录。

## 练度卡模组名称依赖错误猜测

原 `equip_display_name` 将模组 ID 数字的奇偶映射到 X/Y，再推算序号；这不是可靠的名称来源，且没有覆盖 A/B/D 等类型。修复后有模组的练度卡从已有 `ensure_uniequip_table` 表缓存读取 `equipDict[id].uniEquipName`；没有元数据时显示 ID，不猜类型或档位。模组等级仍独立使用玩家的 `EquipState.level`。

没有模组的干员不拉模组表；没有另建名称缓存或重复下载流程。模板契约测试显式模拟名称表，新增的名称测试单独验证数据处理，不依赖线上缓存通过。
