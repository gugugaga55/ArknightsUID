# ArknightsUID 审查与修复记录（2026-10-03）

结论：插件整体符合本机 GsCore 0.10.5 的插件组织及接口约定，但原有测试不足以证明完整、准确地拉取数据。本次修复分页游标、缓存失效与测试隔离问题，并对公开源做了独立实网验证。验证范围为当前安装的核心版本；不等同于对所有 GsCore 版本的兼容性承诺。

## 已确认并修复

| 问题 | 影响 | 修复与证据 |
| --- | --- | --- |
| 抽卡下一页游标由毫秒截为秒 | 上游收到错误的 `gachaTs`，后续页可能丢失 | 原样保留上游游标精度及 `pos=0`，仅统计字段转换成秒；请求参数回归先失败（1700000000 ≠ 1700000000123），修复后通过 |
| 断点补拉测试复制了实现中的错误单位 | 错误实现也能通过模拟的分页测试 | 按原始毫秒游标构造分页响应；验证 50 页分段、下一轮续拉和旧秒级断点迁移 |
| 已有存档可能留下旧版本漏页 | 正常增量同步遇到本地检查点即停，无法补更早的缺口 | 增加 `ark抽卡记录 全量`，重新扫描官方仍保留的数据后与本地合并；不先删除本地历史 |
| `ark刷新` 未失效进程内表缓存 | 删除磁盘缓存后，查询仍返回旧表 | 同时清空表 LRU；回归覆盖“查询旧表 → 执行刷新命令 → 查询新表”的实际调用链 |
| 新 payload 继承旧 ETag/Last-Modified | 校验器与内容不对应，后续条件请求可能错误命中 | 200 响应只保存本次校验器；不带校验器的缓存写入清除旧旁车；304 继续按协议合并元数据 |
| pytest 使用线上数据目录 | 配置写回、缓存冷热状态影响测试；不适合安全并发执行 | 导入配置/数据库前重定向真实 `data_store` 的路径到临时目录，不修改核心文件 |
| 真实核心导入测试长期跳过 | 依赖核心已删除的 `TEST_DATA_ROOT_ENV` 属性，兼容性验证缺失 | 使用测试侧隔离工具恢复导入验证，并断言配置、日志、数据库、插件缓存路径均被隔离 |
| 24 个测试隐式访问外网 | 依赖网络或本机缓存；部分测试虽然通过却未测到预期边界 | 在 HTTP 传输层记录并拒绝未模拟请求；在各业务测试显式模拟无关素材和失败响应；保留真实逻辑及协议测试 |
| 基建测试未使用传入的物品索引 | 物品名称断言实际上依赖实时 item_table | 正确注入测试索引，不再借助线上缓存通过 |
| 代理测试关闭其他事件循环的客户端 | 全量运行时 `RuntimeError: Event loop is closed` | 仅关闭本用例创建的客户端，恢复原引用 |

改动复用现有缓存层、分页流程及 GsCore API，没有增加新的通用防御框架、全局重试层或运行时依赖。

## GsCore 对齐检查

- 保留 `__nest__.py`、内层 `Plugins` 与业务 `SV` 的组织方式；与核心 `server.py` 的嵌套加载流程和 `plugin_developer.py` 的脚手架约定一致。
- 真实 `GsServer.load_dir_plugins` / `cached_import` 加载 **14 个模块**成功；注册 **7 个定时任务**且 ID 无重复。
- `ark`、`方舟`、`明日方舟` 强制前缀和禁止空前缀行为通过断言；没有引入手工拼前缀的新分支。
- 配置继续使用 `StringConfig` / GSC 类型，资源路径继续使用 `get_res_path`，数据库沿用核心 ORM，日志和生命周期钩子继续使用核心接口。
- Python 约束为 `>=3.11,<4.0`；插件声明直接使用的 HTTP 依赖，其余核心运行时依赖由 GsCore 提供。
- 核心仓库原有的 `handler.py`、`reload_plugin.py` 工作区改动保持不变。本次变更均在插件仓库。

## 使用与剩余边界

修复生效后，需要补历史缺口的账号可执行一次 `ark抽卡记录 全量`。单类别超过 50 页时会保存断点并提示补拉，之后执行普通 `ark抽卡记录` 继续；反复使用“全量”会重新开始扫描。现有本地记录保留上限仍为 20000 条，官方已清理且本地未存档的数据无法恢复。

本次未使用真实账号凭据调用登录、抽卡、player_info、签到或推送。账号接口由请求协议、分页及脱敏回归验证，不能以公开源成功代替真实账号端到端成功。实际部署后的账号风控、凭据有效性、官方历史保留范围仍需账号联调确认。

没有提交、推送或重启正在运行的机器人。代码修改在工作区，按通常方式重载插件或重启核心后生效。
